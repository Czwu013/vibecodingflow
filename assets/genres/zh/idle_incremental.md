# 放置 / 增量（idle_incremental）

适用：数字自己增长、靠购买升级和周期性重置推进的放置类游戏。

## 验收基准

| 维度 | 4 分是什么样 | 参考对象 |
| --- | --- | --- |
| 能用 | 离线收益正确；大数不溢出且显示正常；存档可靠（这一项最关键，丢进度是最伤的） | — |
| 看着 | 数字格式清晰（K / M / B 或科学计数），不抖动；可购买项的状态一眼可见 | — |
| 手感 | 点击和购买即时反馈；数字跳动有满足感 | — |
| 清晰 | 玩家知道下一个目标是什么，哪项购买性价比最高 | — |
| 想继续 | 目标总在"再等一会就能买"的距离；重置（声望）后有新的维度被打开 | 例：Cookie Clicker、Antimatter Dimensions 的推进节奏 |

## 手感参数起点

| 参数 | 常见起点 | 说明 |
| --- | --- | --- |
| 各项成本增长系数 | 每次购买约 1.07–1.15 倍 | 越大越快遇到墙 |
| 产出速率 | 按"首个自动项约 1 分钟买到"定 | 前期节奏 |
| 离线收益效率与上限 | 如 50%、上限 8–24 小时 | 避免离线收益吞掉主动游玩 |
| 里程碑倍率 | 每 25 / 50 / 100 级 | 给持续购买一个小目标 |
| 声望公式 | 按首次重置约 1–2 小时定 | 重置必须带来新东西 |
| 自动存档间隔 | 10–30 秒 | 防止意外丢进度 |

## 常见返工点

- 增长曲线停滞（等待过长）或过快（失去意义）
- 大数显示难读
- 离线收益算错
- 重置没有新鲜感，只是把数字清零
- 数字刷新过于频繁导致闪烁

## 体验路线示例

- 开局 1 分钟 → 买到第一个自动产出项，数字自己增长
- 关闭页面 5 分钟后重开 → 离线收益合理、提示清楚
- 连续玩 15 分钟 → 总有下一个"快到了"的目标
- 到达第一个重置点 → 新机制出现，值得重来
- 数字很大时 → 显示仍然整齐

## 一分钟测试

一分钟内应当买到第一个自动产出项，并看到数字自己在增长。

## 灰盒阶段验什么

只有数字和按钮。验**增长曲线**：写脚本模拟 N 小时的进度，看每个阶段的等待时间是否合理，作为"AI 已验证"的证据。
