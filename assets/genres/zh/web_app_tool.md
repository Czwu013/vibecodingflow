# 网站 / 工具（web_app_tool）

适用：网站、网页应用、小工具。这类项目没有"手感"的游戏含义，对应的是**交互响应**。

## 验收基准

| 维度 | 4 分是什么样 | 参考对象 |
| --- | --- | --- |
| 能用 | 主流程能跑通；出错有提示而不是白屏；刷新或后退不丢数据；主流浏览器和手机宽度都能用 | — |
| 看着 | 层次、对齐、留白、字号一致，不像模板拼凑 | — |
| 手感 | 点击和输入的反馈让人感觉即时；加载中有状态；动效不拖慢操作（交互响应） | — |
| 清晰 | 新用户不看说明就能完成主任务；按钮和文案含义明确；空状态和错误状态有引导 | — |
| 想继续 | 解决了真实问题；比原来的办法更快；用户愿意回来用 | — |

## 手感参数起点

这里的"手感"是交互响应，参数是设计变量。

| 参数 | 常见起点 | 说明 |
| --- | --- | --- |
| 主题色 / 字号 / 间距 / 圆角 | 用一组设计变量集中管理 | 改一处全局生效 |
| 动效时长与缓动 | 0.15–0.3 秒 | 太长会觉得慢 |
| 输入防抖延迟 | 200–400 毫秒 | 搜索框等 |
| 分页大小 | 按场景定，常见 20–50 | |
| 请求超时与重试 | 按接口定 | 要有失败提示 |
| 触控目标尺寸 | 不小于约 44 像素 | 手机上防误触 |

## 常见返工点

- 手机宽度下布局崩坏
- 缺少加载、空、错误这三种状态
- 文案和按钮名称含糊
- 颜色对比不足，文字难读
- 表单校验体验差（提交后才告诉你错在哪）
- 速度慢（大图、阻塞渲染）

## 体验路线示例

- 第一次打开，不看任何说明完成主任务 → 能完成且知道下一步
- 断网或输入非法内容 → 有明确的错误提示，不白屏
- 把窗口缩到手机宽度 → 布局正常，按钮能点
- 刷新页面 → 状态保留或有明确提示
- 完成主任务后 → 知道结果在哪里、怎么继续

## 一分钟测试

新用户一分钟内应当完成一次主任务。

## 灰盒阶段验什么

线框加真实数据。验**流程**和**信息架构**，通过之后再上视觉。
