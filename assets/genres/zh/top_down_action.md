# 俯视角动作（top_down_action）

适用：俯视角的近战或射击战斗，包括双摇杆射击和轻量 ARPG。

## 验收基准

| 维度 | 4 分是什么样 | 参考对象 |
| --- | --- | --- |
| 能用 | 移动、战斗、拾取全流程不崩；碰撞稳定；敌人 AI 不会卡死 | — |
| 看着 | 角色、敌人、攻击范围、伤害判定一眼分清；受击有可见反馈 | — |
| 手感 | 攻击的前摇和后摇适中；命中有停顿、击退或震屏；闪避有可感知的无敌帧；瞄准精确 | 例：Hades 的战斗反馈 |
| 清晰 | 敌人的攻击有可读的预警；玩家知道自己为什么受伤 | — |
| 想继续 | 战斗有攻防转换的节奏；战利品或成长带来新玩法 | — |

## 手感参数起点

| 参数 | 常见起点 | 说明 |
| --- | --- | --- |
| 移速 / 加速 | 按战斗尺度定 | 先定移速，再定攻击距离 |
| 攻击前摇 / 判定 / 后摇 | 各 0.05–0.3 秒 | 前摇太长显笨，太短没有分量 |
| 命中停顿 | 2–6 帧 | 最便宜的"打中了"的感觉 |
| 击退距离 | 按敌人体型 | |
| 闪避距离 / 时长 / 无敌帧 | 0.2–0.4 秒 | 无敌帧要看得出来 |
| 敌人感知范围 / 攻击间隔 | 每类敌人单独一套 | |
| 敌人攻击预警时长 | 0.3–0.8 秒 | 要足够让人反应 |
| 受击无敌时长 | 0.3–1.0 秒 | |

## 常见返工点

- 攻击没有打击感（缺停顿和反馈）
- 敌人攻击不可读，玩家觉得被偷袭
- 闪避不好用，或无敌帧时机不对
- 镜头不跟手
- 鼠标或手柄的瞄准偏差

## 体验路线示例

- 对单个敌人连续攻击 → 命中反馈明确
- 躲避敌人的前摇攻击 → 预警可读且来得及躲
- 同时面对 3 个敌人 → 画面不糊，仍能分清谁要攻击
- 闪避穿过攻击 → 无敌帧生效
- 被打中 → 知道是被谁、被什么打中

## 一分钟测试

一分钟内应当击败第一个敌人，并感到"打中了"。

## 灰盒阶段验什么

方块和扇形判定。验**打击感参数**（命中停顿、击退）和**敌人攻击前摇是否可读**。
